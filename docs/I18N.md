# Internationalization

**English** | [Italiano](I18N.it.md)

## Catalogs and fallback

`alterecho/locales/en.json` is the reference catalog; `it.json` is the complete Italian catalog. Both Python and Svelte consume these same JSON files, so API error codes have one definition. Keys describe presentation messages and remain stable independently of their wording. Values are strings or plural-category objects. `_meta` contains the native language name and Python number/date/plural formatting metadata.

Python uses `importlib.resources`, a context-local language and the standard library. Vite's eager glob bundles every JSON catalog into the frontend. No runtime translation service or Internet connection is needed. Missing translated keys fall back to English. Missing reference keys produce a readable generic message and debug diagnostics; they never crash a client. Catalog tests reject duplicate keys, mismatched key sets and incompatible placeholders.

```json
{
  "_meta": {
    "name": "English",
    "plural": "n != 1",
    "pluralCategories": ["one", "other"],
    "decimal": ".",
    "group": ",",
    "dateFormat": "%Y-%m-%d %H:%M"
  },
  "web.delete_topic": "Delete “{topic}”?",
  "web.messages": {"one": "{count} message", "other": "{count} messages"}
}
```

Parameters are named and substituted as plain text, not HTML or executable expressions. Literal JSON braces remain unchanged. Svelte escapes translated output; only the existing sanitized conversation Markdown renderer handles HTML. Frontend numbers, dates/times and plurals use `Intl`. Python uses catalog separators/date format and the standard gettext plural-expression compiler. Additional plural forms can be declared through `pluralCategories` and a gettext expression without language-specific application branches.

## Browser behavior

Automatic selects the first supported language from ordered `navigator.languages`, normalizing regional variants such as `it-CH` and `en-GB`. No match falls back to English. Manual English/Italian choices override browser preferences. `alterecho-language` in local storage persists the selection; Automatic returns to detection. If browser storage is unavailable, the current session still works without persistence. The document's `lang` updates too.

Selectors are available before login, in the sidebar/settings and inside confirmation dialogs. Svelte stores update labels, open dialogs, errors and notifications without reloading. They do not navigate, abort SSE, recreate conversation components, reset forms or clear scroll state. Preferences belong to that browser origin/profile and do not become shared server settings. A separate browser/profile keeps its own preference; tabs sharing the same storage do not receive a forced language change during an active session.

## CLI detection and precedence

1. Explicit global `--lang` option.
2. `ALTERECHO_LANG`, if set.
3. Saved preference in `client-language.json`, beside `client.json`.
4. System locale.
5. English fallback.

`auto` at the selected precedence level requests system detection rather than consulting lower explicit preferences. A temporary command-line/environment override is never saved. Settings **Language / Lingua** changes only the persistent client preference; active explicit/environment overrides remain authoritative.

On headless systems, detection checks `LC_ALL`, then ordered `LANGUAGE`, `LC_MESSAGES` and `LANG`. Without usable environment settings, Windows uses `GetUserDefaultLocaleName`; Linux/macOS use Python's locale information. Codes normalize `_`/`-`, encoding/modifier suffixes and regional variants. Unsupported or unavailable locales fall back to English. `C`/`POSIX` selects the fallback when no supported preference exists.

```sh
alterecho --lang en help
alterecho --lang it help
alterecho --lang auto status
```

Set environment variables with your shell, e.g. `export ALTERECHO_LANG=it` or `$env:ALTERECHO_LANG='it'`. Commands, flags, API routes, enum values and configuration keys never acquire translated aliases. The CLI language does not select an inference language.

## Server errors and compatibility

Server-owned diagnostics use English. Application errors preserve `detail` and add stable `code`/`params` where available. Strict validation preserves the existing list of `loc`/`msg`/`type` details and adds a generic translatable validation code. Snapshots/provider diagnostics/failure events may add `error_info`; existing fields remain intact. Known credentials are redacted from details and parameters.

Clients translate recognized codes in their own locale. Unknown legacy/server errors and external provider diagnostics remain readable as supplied. There is no global server-language preference and no `Accept-Language`-driven mutation of shared state.

Topics, prompts, roles, personalities, debate positions, model responses, canonical JSON, checkpoints and Codex sessions are data. They never pass through automatic translation. Existing Italian prompt/default text remains for compatibility. Offline exports retain their original conversation content and existing wrapper; changing UI language does not rewrite them or migrate histories.

## Add another language

1. Copy `en.json` to a new catalog such as `fr.json` or `zh-CN.json` and use the language's native name in `_meta.name`.
2. Translate values, preserving keys and placeholders. Set Python separators/date format and gettext plural expression/categories; provide the `Intl` plural categories needed by that locale.
3. Keep commands, model/provider IDs, API paths and technical examples unchanged. Do not translate interpolated user data.
4. Run Python catalog tests and frontend tests/checks, then rebuild the frontend and package. Discovery and selectors use the available catalog files; application code needs no new language branch.
5. Review context, accessibility labels and real browser layouts with a speaker of the language. Do not add empty catalogs that imply unsupported translations.

Do not ship translator-only tooling, online translation calls or credentials. Comment/docstring language for new code is English. Keep [English](../README.md)/[Italian](../README.it.md) documentation equivalent, preserving historical documents under their original paths.

## Packaging and tests

Setuptools package data and `MANIFEST.in` include `locales/*.json`; PyInstaller's existing data collection includes them. Docker copies catalogs into the frontend stage and Python package. Test commands:

```sh
python -m unittest tests.test_i18n -v
python -m unittest discover -q
cd web
npm run check
npm test
npm run build
npm run test:e2e
```

All operational tests use mocks/demo, never real provider inference. [Actual results and remaining checks](VERIFICATION-I18N.md).
